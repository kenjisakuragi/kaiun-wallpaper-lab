# 03 コンテンツ仕様

## 1. 画像（待ち受け）
| 項目 | 値 |
| --- | --- |
| 生成サイズ | 1024×1536（縦長） |
| 配布・投稿用 | 1080×1920 の JPEG（品質90）。Threads の画像は幅320〜1440px・8MB以下（二次情報、`docs/04` で要確認）に収まる |
| LINE プレビュー用 | 長辺480 の JPEG（容量上限は `docs/04` で要確認） |
| 文字 | 画像内に文字を入れない。日付は投稿文・動画テロップ・LINE 文面で伝える |
| 構図 | ロック画面の時計が重なる上部25%と下部15%に主要モチーフを置かない |
| テイスト | `prompts/image_birthday.md` のスタイルガイドに固定 |
| 禁止 | 実在の人物・キャラクター・ブランド・寺社の写真や意匠、特定宗教のシンボル |

### 1-1. 誕生日版
- 366日分（2/29 を含む）。題材は `data/birthdays.yaml`（`date`、`color_name`、`color_hex`、`motif`、`keyword`）。
- 守護カラーとモチーフは**このプロジェクト独自の設定**で、伝統や学説を名乗らない。設定ルールを `birthdays.yaml` の先頭コメントに明記する。
- 初版の `birthdays.yaml` は Claude Code が規則に沿って生成し、人がレビューしてから画像生成に進む。

### 1-2. 共通版（LINE の B群）
- 1種類で開始。誕生日版と同等の品質・テイスト。季節の差し替えは必要になったら追加する。

### 1-3. 開運日版（2026-10-04 変更）
- 開運日の**種類ごとに1枚**（`data/calendar/README.md` の type 7種＝7枚）を作り、同じ種類の開運日で使い回す。開運日そのもの（日付）は自動計算せず、人が出典付きで `data/calendar/YYYY.csv` に入力する。
- 使い回しが目立つ・反応が落ちるなど必要が出たら、同じ種類の2枚目以降を追加する（key は `ichiryumanbaibi-2` のように連番）。

### 1-4. アファメーション版（2026-10-04 追加）
- 12枚で開始し、投稿ごとに使い回す（言葉は本文側で毎回変える）。必要になったら追加する。

### 1-5. 枚数の考え方（2026-10-04 決定）
- 初回は 誕生日366＋開運日7＋アファメーション12＋共通1＝386枚。量産前に10枚を試作して画風を固め、作り直しを1割以内に抑える。
- 以降はアジャイルに、ニーズ（反応・LINE の要望・使い回しの目立ち）が見えたものだけ追加生成する。

## 2. Threads の投稿
### 2-1. 本投稿（毎日1本）
- 形式：画像1枚＋本文。カルーセルは初期は使わない（1枚の方が比較しやすい）。
- 本文：150〜300字（上限500字）。構成：
  1. 用途（例：「今日3月15日生まれさんの守護カラー待ち受け」）
  2. 守護カラー名とモチーフの一言
  3. 呼びかけ：「あなたの誕生日も4けたでリプしてね。守護カラーをお返事します（例：0315）」
  4. 導線：「誕生日だけの待ち受けはプロフィールのリンクのLINEで」
  5. 定型文：「※画像はAIで作成しています／占い・おまじないとして楽しんでください」
- ハッシュタグ：0〜1個（Threads のトピックタグを使う場合のみ）。
- 本文に外部リンクを入れない（リンクはプロフィールのみ）。
- 開運日の当日・前日は開運日版を投稿し、呼びかけは同じ。
- アファメーション版（2026-10-04 追加）：1の用途を「今日のアファメーション」とし、2で `data/affirmations.yaml` の言葉を1つ紹介する。3〜5は同じ。言葉は画像に入れず本文に書く。

### 2-2. 自動返信（誕生日リプへの返事）
- 1〜2文、80字以内。内容：「その日生まれさんの守護カラーは『{color_name}』、キーワードは『{keyword}』です」＋短い一言。月日の数字は返信文に入れない（`docs/05` の保存ルールと揃えるため）。
- 画像・リンク・ハッシュタグを入れない。LINE への誘導文も毎回は入れない（入れるのは3回に1回まで。宣伝の連投に見えるのを避けるため）。
- テンプレートは `prompts/threads_replies.md`。言い回しを複数用意し、直近200件と類似しないものを選ぶ。

## 3. Instagram リール
| 項目 | 値 |
| --- | --- |
| 尺 | 12〜15秒 |
| 形式 | 1080×1920、30fps、H.264、AAC |
| 構成 | 0〜1秒：画像全面＋テロップ「○月○日生まれの守護カラー」／1〜12秒：ゆっくりズーム／最後2秒：「保存して待ち受けにしてね」 |
| 音 | 無音または権利がクリアな BGM。アプリ内の楽曲を使う場合は手動 |
| フォント | 商用利用可のものを `assets/fonts/` に置き、ライセンスを保存 |

キャプション：80〜200字。用途→守護カラーとモチーフの一言→導線「誕生日だけの1枚はプロフィールのリンクのLINEで」→定型文→ハッシュタグ3〜5個。

## 4. 共通ルール
- 効果の断定・煽り・健康効果を書かない（プロンプトで指示。NG ワード検査は `NG_WORD_MODE` に従い、初期値 `warn` では記録のみ。`docs/08` §2）。
- 投稿文は媒体ごとに別生成。直近90日の投稿文と完全一致は不可、文字 bigram の Jaccard 類似度 0.8 以上も再生成（閾値は設定値）。

## 5. LINE 文面
`prompts/line_messages.md` のテンプレートに変数を差し込む（LLM で毎回生成しない）。A/B で文面差を最小にし、差は画像だけにする。

### 5-1. 今日のひと言（2026-10-04 追加）
- トリガー：`ひと言` を含むテキスト（リッチメニューのボタンから送る想定）。月日の解釈より先に判定する。
- 内容：`data/affirmations.yaml`（人がレビューした短い言葉のリスト）から、Asia/Tokyo の日付で決まる1件。同じ日は誰にでも同じ言葉。
- 送信：Reply API（通数に数えない）。テンプレートは `prompts/line_messages.md` の daily_word。画像は付けない。
- 記録：`deliveries.type = daily_word_reply`、`counted = 0`。

## 6. 投稿カレンダー
- `posts` に投稿予定を事前登録する（`docs/05`）。Threads と Instagram は同じ日に同じ題材を使ってよいが、文面は別。
- 誕生日版は当日〜7日以内の誕生日を優先。開運日の当日・前日は開運日版を優先。
- 題材の比率は `docs/01` §4 と `docs/09` #15 に従う。
