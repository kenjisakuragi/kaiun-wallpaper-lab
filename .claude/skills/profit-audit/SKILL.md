# profit-audit（利益の点検）

作業量やアクセス数を増やすことではなく、顧客への提供価値を保ちながら、実際に残る利益を増やすための手順。
数字・顧客の声・施策の効果を捏造しない。推測は「仮定」、分からないものは「未確認」と書く。

## 1. データの棚卸し（読み取りだけ）
集めて、置き場所を確認する。氏名・メール・LINE userId などの個人情報は分析に不要なので入れない。
- SNS：投稿別の表示・リプ・誕生日リプ・フォロー（E-01 のキットの記録 `log/<日付>`、Threads インサイト）
- 計測：`link_clicks`（/go/threads・/go/instagram・/go/chat）、LINE 友だち増減（users）
- バックエンド（AI チャット占い、別プロジェクト）：流入元 ref 別の登録・課金・課金額・返金・1通あたり AI 原価（取得できる範囲）
- 費用：決済手数料率、固定費（LINE プラン・ドメイン）、広告費、人の作業時間（指示・確認・修正・問い合わせ対応を含む）

確認すること（コードで確かめ、一覧を残す）：
- 同じ注文・同じ日の重複、返金が翌月にずれていないか、税込／税抜、集計期間とタイムゾーン（Asia/Tokyo）がそろっているか、空欄をゼロにしていないか

## 2. 再計算できる形で計算する
1. `data/private/profit-assumptions.yaml`（Git 管理外）を更新する。各値に `status`（measured / assumed / unknown）と `source`（期間・出典・理由）を付ける。測定値が出たら assumed を measured に置き換える。
2. `pnpm profit:audit` を実行する → `out/profit/report.md`。文章で足し算しない。
3. 読むところ：広告費控除後の限界利益、LINE 友だち1人あたり限界利益（＝獲得単価の上限の目安）、無料体験の AI 原価、未確認の入力。

## 3. 改善候補を最大3件に絞る
SNS、商品設計（無料体験の量・価格）、導線（LINE の案内）、既存顧客支援、コスト削減から、データで検討できるものだけ。各案に付ける：
- 根拠（確認済みの事実）と仮説（仮定）を分けて
- 必要なデータ、実装内容、費用、顧客へのリスク、比較方法、判断に必要な期間

## 4. 最初に検証する1件を決めて記録する
- `docs/jv-experiments.md` に「誰の、どの行動を、何によって進め、いつ、何を見て判断するか」と成功／失敗／判定不能の基準を書く
- 判断が要るものは `docs/jv-decisions.md` に判断依頼の形で書く（推奨案・根拠・費用・希望回答日。返答がないことを承認とみなさない）
- 結果は確認日・データの期間・出典・分母つきで `docs/jv-pdca.md` に残す

## 人の承認なしにしないこと
投稿、メール・LINE の送信、広告の出稿・増額、課金・返金、契約・価格の確定、本番サイトの更新、顧客情報の外部送信。
